# Project Rules for niagara-launcher

- **No Local Gradle Builds**: Do NOT run `./gradlew assembleDebug` or build APKs locally on this sandbox to save disk space. Always clean `app/build` if created.
- **Local Commit First, Push Upon Confirmation**: After implementing each feature or fixing bugs in a multi-step batch, run `git add -A && git commit -m "<message>"` locally, and do **NOT** automatically run `git push`. Once **all** planned tasks in the current batch are completed and verified, explicitly ask the user whether to push to GitHub (`git push origin main`), and only execute the push after receiving confirmation. With the free-tier `workflow_dispatch` setup, pushing code no longer burns Actions minutes automatically—trigger `Build and Release Debug APK` manually in GitHub Actions only when you want an APK built and published.
- **Memory Optimization After Tasks**: Whenever a task or batch of edits finishes, remind the user to optimize sandbox memory—such as stopping idle Gradle/Kotlin daemons (`./gradlew --stop` or ending lingering Java/Kotlin compiler processes when not actively running tests), closing unused background/test processes, cleaning `/tmp` scratch files if created, and checking `free -h` to keep memory headroom sufficient.
